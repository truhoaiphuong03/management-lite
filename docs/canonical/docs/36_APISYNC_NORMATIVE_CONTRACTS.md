# API-SYNC — Normative endpoint contracts (V0.1)
Version: 0.1.0-doc.11 | 2026-10-08 | DESIGN ONLY | Supersedes conflicting legacy conditional statements in docs 05, 24–27, 34–35. Owner decisions C01–C06 unchanged.

## Universal protocol
Prefix `/api/v1`; JSON snake_case, UTC ISO 8601, UUID, integer VND and seconds. Success `{success:true,data:{...},meta:{request_id}}`; error `{success:false,error:{code,message,details:[]},meta:{request_id}}`; 204 empty. Cookie session + CSRF/Origin on mutation; backend scoped authorization on every operation. `If-Match` strong entity version for updates/decisions; missing => 428 `PRECONDITION_REQUIRED`; stale => 412 `PRECONDITION_FAILED`; semantic conflict => 409 `CONFLICT`; invalid state => 422 `INVALID_TRANSITION`; unauthenticated 401; forbidden 403; cross-workspace hidden resource 404. Mutations use Idempotency-Key when contract says; same key+same canonical payload returns original non-secret result; same key+different payload => 409. Never cache plaintext secret response.

## AUTH C06 — active workspace
`POST /auth/login` `{identifier,password}` => 200 `{user,active_workspace:{id},session_expires_at}` only if exactly one **preauthorized active binding** is resolved by backend for V0.1. If zero or multiple eligible bindings without unique preauthorized binding, fail closed with generic `409 WORKSPACE_CONTEXT_UNRESOLVED` after credentials verified; no session granting access, no arbitrary first membership, no workspace selector. Binding provisioned by authorized Owner/admin workflow, not client-supplied ID. `GET /auth/me` => `{user,active_workspace,permissions}`; memberships may be returned for audit but never switch context. Requests never accept workspace_id as authority; session binding is authoritative; membership/workspace status rechecked. Any change of binding revokes old context/session. Existing global user model unchanged; provisioning a binding when multiple memberships exist remains an explicit operational prerequisite, not a hidden automatic selection.

## ATT C01 — forgotten clock-out
`POST /attendance/shifts/{id}/correction-requests` (shift owner only, active membership) request `{reason,claimed_clock_out_at?,evidence_note?}` with `If-Match` shift version and `Idempotency-Key`. `claimed_clock_out_at` is **non-authoritative** evidence only. Response 201 `{request_id,status:"pending",shift_id,requested_by,created_at,version}`. Only an open shift (`working` or `paused`) is eligible; no automatic clock-out. One active request per shift; repeated identical key safe; contradictory requests =>409. Request cannot itself create paid seconds or approve attendance. Owner's own shift can have a request, but must not be self-approved.

`POST /attendance/correction-requests/{id}/decide` Owner only; `{decision:"accept"|"reject",reason,clock_out_at?,break_resolution?:{break_id,ended_at,evidence_note}}`, `If-Match` request version, `Idempotency-Key`. Accept requires Owner's **explicit** clock_out_at (not defaulted to now or claimed value), valid UTC interval, complete nonoverlapping paid/unpaid segment proof, and explicit end for every open break; `break_resolution.ended_at` must be evidence-supported and <= clock_out_at. Reject requires reason; leaves shift unchanged. For paused shifts with unresolvable break end, fail closed with `422 BREAK_RESOLUTION_REQUIRED` and keep request pending; no inferred working time. On accept, transaction locks shift/request/breaks, validates overlap, records decision, closes shift with immutable `attendance_shift_versions` snapshot, sets current version `unreviewed`, writes audit. Existing approved snapshots retained. Separate Owner review endpoint approves current version only; no employee self-review and no Owner self-approval. If source was finalized in payroll, no rewrite: append-only correction path only. Missing/stale versions =>428/412; cross-workspace =>404.

`POST /attendance/shifts/{id}/reviews` Owner, `{decision:"approve"|"reject",reason?}` with If-Match, Idempotency-Key; only completed current immutable version, reviewer != shift employee user; approval and source version locked transactionally. A correction decision is **not** an approval.

## REP C02
`POST /reports/daily/{id}/revisions` report owner, report `submitted` only; `{entries:[{work_type,reported_count,notes?}],reason?}`, If-Match report version, Idempotency-Key. Response 201 `{report_id,revision_id,revision_number,status:"submitted",submitted_at,version}`. Insert immutable new revision with author/time, preserve prior submitted revision and historical submitted_at; update current_revision pointer transactionally. PATCH remains draft-only; initial submit uses `/reports/daily/{id}/submit`. No Owner approval invented, no automatic KPI conversion, no other employee edits. `GET /reports/daily/{id}/revisions` Owner or report owner only.

## ACC C05
`PUT /accounts/{id}/secrets` Owner only; `{secret_type,secret_value,reauth_proof}`; If-Match account version + CSRF + action-bound proof + Idempotency-Key (only safe metadata, never secret bytes or plaintext response). Proof binds Owner user/session/account/action `secret_write`, <=5min, single-use consumed in same transaction as secret update; stale/wrong action/session/account denied with `403 REAUTH_REQUIRED`. AEAD encryption with key outside DB, AAD workspace/account/type/version, audit without values. 200 `{secret_version,updated_at}` and `Cache-Control:no-store`; never reveal secret. `/accounts/{id}/secrets/reveal` requires a distinct `secret_reveal` proof, one-time, non-cacheable. A failed transaction must not consume proof without update; retry requires a fresh proof if transaction outcome is uncertain; idempotency record must not store secret or reauth proof.

## PAY C04 + PAY-02
`POST /payroll/periods/{id}/calculate`: draft only, Owner, If-Match and idempotency; compute from current completed approved attendance version; exact integer seconds and rational NUMERIC arithmetic, split local day/rate/break, sum numerator per employee-period and half-up once for nonnegative base; no Owner payroll item. Return `{calculation_revision,items,blocking_errors}`. `POST /payroll/periods/{id}/finalize`: Owner, If-Match, idempotency, transactionally revalidate all sources/rates, reject **entire period** if any employee `net_vnd < 0` with 422 `NEGATIVE_NET_PAY` and affected item IDs only; no clamping/carryforward/partial finalize. Also reject missing rate, stale approvals, overlaps. Finalized snapshots immutable, corrections append-only, tax/settlement out of scope.
